`finalidade` vai na raiz, em maiúsculas. Não envie `finEvt` no JSON.

| `finalidade` | Referências no JSON | `finEvt` posterior |
| --- | --- | --- |
| `ORIGINAL` | Nenhuma. Omita `chave_referencia` e `sequencia_referencia`. | `11` |
| `DEVOLUCAO` | `chave_referencia` no grupo e `sequencia_referencia` em cada operação. | `31` |
| `CANCELAMENTO` | As mesmas referências da devolução. | `41` |

## Referência

Devolução e cancelamento exigem `chave_referencia` e `sequencia_referencia` de um D-4201 original com status aprovado, na mesma empresa e no mesmo ambiente.

| Situação | Resultado |
| --- | --- |
| Chave com 53 caracteres sem original aprovado | Rejeitada |
| Sequência inexistente no original aprovado | Rejeitada |
| Código `REFERENCE_NOT_OFFICIALLY_APPROVED` | A referência não aponta para um original aprovado |

Os exemplos de devolução e cancelamento mostram só a estrutura. O envio real depende de um original aprovado.

## Devolução (estrutura)

```json
{
  "versao": 1,
  "empresa_id": 10,
  "origem": "ERP_APOSTAS_SINT",
  "competencia": "2026-11",
  "finalidade": "DEVOLUCAO",
  "grupos": [
    {
      "id_origem": "G-SINT-DEV-001",
      "chave_dere": "12345678901BBBBBBBBBBBBBBBBBBBBBBBB202611050500000002",
      "chave_referencia": "12345678901AAAAAAAAAAAAAAAAAAAAAAAA202611050500000001",
      "presencial": false,
      "apostador": {
        "cpf": "52998224725",
        "municipio": "3550308"
      },
      "operacoes": [
        {
          "data_hora": "2026-11-05T18:00:00.000+00:00",
          "valor": "100.00",
          "sequencia_referencia": "001"
        }
      ]
    }
  ]
}
```

`CANCELAMENTO` usa a mesma forma, com `"finalidade": "CANCELAMENTO"`.
