## Base e autenticação

| Item | Valor |
| --- | --- |
| BASE (homologação) | `https://hom.portalgsf.com.br` |
| Prefixo | `/api/v1/` |
| Trailing slash | Obrigatório (`/nfse/`, `/nfe/`, …) |
| Auth | `Authorization: JWT <token>` |
| Content-Type JSON | `application/json; charset=UTF-8` |
| CNPJ | Somente dígitos — ex.: `22760852000110` |
| Datas | `DD/MM/AAAA` |
| País (Brasil) | `1058` |

<Warning>
O header de autenticação usa o prefixo **`JWT`**, não `Bearer`.
</Warning>

## Endpoints

| Método | Path público | Função |
| --- | --- | --- |
| `POST` | `/api/v1/auth/token/` | Obter token |
| `POST` | `/api/v1/nfse/` | Receber lote NFS-e |
| `POST` | `/api/v1/nfse/consulta/` | Consultar retorno NFS-e |
| `POST` | `/api/v1/nfe/` | Receber lote NF-e (JSON) |
| `POST` | `/api/v1/nfe/consulta/` | Consultar retorno NF-e |
| `POST` | `/api/v1/nfe/sefaz/` | Enviar XML SEFAZ |

## Fluxo recomendado

<Steps>
  <Step title="Autentique">
    Obtenha o JWT em `/api/v1/auth/token/` com o usuário técnico.
  </Step>
  <Step title="Envie o documento">
    Use NFS-e, NF-e ou SEFAZ conforme o tipo de integração.
  </Step>
  <Step title="Guarde a correlação">
    Persista o código de origem (`codigoOrigem` / `idNfErp`) e, na NFS-e, o `nroProtocolo`.
  </Step>
  <Step title="Consulte o retorno">
    Chame `/nfse/consulta/` ou `/nfe/consulta/` com CNPJ + `cod_origem` até obter status final.
  </Step>
</Steps>

## Códigos HTTP

| HTTP | Significado | O que fazer |
| --- | --- | --- |
| `200` | Requisição aceita / retorno disponível | Leia o corpo. Em envios assíncronos, ainda pode ser necessário consultar. |
| `204` | Consulta sem retorno pronto | Aguarde e consulte novamente. |
| `400` | Payload inválido | Corrija os campos e reenvie. |
| `401` | Token inválido ou expirado | Gere um token novo. |
| `412` | Parâmetro obrigatório nulo | Informe `cnpj` e `cod_origem`. |
| `500` | Erro interno | Registre o horário e o código de origem; contate o suporte. |
